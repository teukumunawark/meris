# Item Name Correction Design Specification

This document details the architecture and implementation design for the Inline Item Name Correction feature. This allows users to fix typos generated by the AI receipt scanner.

## 1. Objectives
- Enable users to correct item names directly from the session page.
- Sync renamed items in real-time across all connected session participants using Server-Sent Events (SSE).
- Follow a seamless inline editing UX that blends with the luxury-editorial design system.

## 2. API Design (Backend)

### Endpoint
- **URL**: `PUT /session/{id}/item/{itemId}/rename`
- **Method**: `PUT`
- **Headers**:
  - `Content-Type: application/json`
- **Request Body**:
  ```json
  {
    "name": "New Item Name"
  }
  ```
- **Response**:
  - `200 OK` on success.
  - `400 Bad Request` if the session ID, item ID, or new name is invalid.
  - `404 Not Found` if the session or item does not exist.

### Database Operations
- Find the `Item` matching the `id` (item ID) and `session_id` (session ID).
- Update the `name` column in the `items` table.

### Real-Time Update
- Once the database is updated, trigger `h.broadcastFullState(ctx, sessionID)` to notify all connected clients via SSE.

---

## 3. Frontend Architecture

### Custom Hook (`useClaimSession.ts`)
- Expose a new function `renameItem(itemId: string, newName: string): Promise<boolean>`.
- **Optimistic State Update**:
  - Instantly update the name of the matched item in the local `items` state.
- **Backend Sync**:
  - Make a `PUT` request to `${backendUrl}/session/${sessionId}/item/${itemId}/rename`.
  - If the sync fails, roll back to the previous name in the state.

### Card Component (`ItemCard.tsx`)
- Maintain local state `isEditing` (boolean) and `editValue` (string).
- Display an edit pencil button next to the title when the user is hover-interacting and `isJoined` is true.
- When `isEditing` is true:
  - Transform the text title into a borderless input field with matching typography (`font-sans text-lg sm:text-xl md:text-2xl`).
  - Render small Check (Save) and X (Cancel) buttons.
  - Listen for key events: `Enter` triggers save, `Escape` triggers cancel.
